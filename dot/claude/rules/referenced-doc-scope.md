## 参照される側には自分の責務だけを書く

スクリプトのヘッダコメント・SKILL.md・rule・agent 定義のように、他から参照・利用される側の
記述には、自分の責務と契約（何を入力に取り、何を返し、何を保証するか）だけを書く。誰がそれを
参照するか、利用者ごとにどう使われるかは書かない（「この出力を読むのは X だけ」「Y はこれを
Z の確認にだけ使う」等）。利用関係の記述が要るなら、利用する側に書く。

対象は Markdown に限らず、`bin/` のスクリプトのコメントのような任意のファイル種別に及ぶので、
`paths` を付けず常時ロードする。

利用関係は利用する側の事情で変わる。参照される側に書くと、利用者が増えたり使い方を変えたり
するたびに参照される側も直す必要が生まれ、直し漏れればそのまま嘘になる。しかも利用者を
変える PR の差分には参照される側の記述が現れないので、レビューでも拾われにくい。契約は
利用者が入れ替わっても変わらないので、そちらだけを書いておけば腐らない。

実例: dotrc/docs/incidents/callee-doc-names-callers.md
