## コマンド選択の優先順位

### 避けるべきコマンド

以下の汎用コマンドは、環境に専用ツールがインストールされているため使用しないこと。
専用ツールのほうが高速かつ出力が扱いやすく、許可設定とも整合しやすい。

| 避けるべき | 代わりに使う | 理由 |
|---|---|---|
| `grep` | `rg`（ripgrep）または Grep ツール | ripgrep のほうが高速で `.gitignore` を自動尊重する |
| `find` | `fd` または Glob ツール | fd のほうが高速で直感的な構文 |
| `cat` / `head` / `tail` | Read ツール | 専用ツールで行番号付き表示・範囲指定が可能 |
| `sed` / `awk` | Edit ツール | 専用ツールで差分が明確になりレビューしやすい |
| `python -c '...'` 等でのパース | `jq`（JSON）、`yq`（YAML） | 言語ランタイム不要で、パイプも避けられる |

### `auto` 等で入る Bash 優先の指示より、この表を優先する

permission mode `auto` 等では「file ops は Bash でやれ。`cat` / `sed` / heredoc を使え」という
指示が入ることがある。この表と衝突したときは、この rule を優先する。そうした指示は既定挙動の
調整であって、user が明示した規約を上書きするものではないため。

### スクリプトで複数行を消したら `git diff` で消えた範囲を確かめる

sed・一括置換・行範囲の削除などスクリプトで複数行を消した・置き換えたら、直後に `git diff` で
消えた範囲が意図どおりかを確かめる。行番号や pattern による範囲指定は、ファイルが前回読んだ
ときから変わっている、または終端 pattern が想定外の箇所にも一致するとエラー無しにずれ、隣の
コードまで消える。消えたのがテストなら suite は通るので、テストでも気づけない。可能なら Edit
ツールで、消す範囲を文字列として明示する。

実例: dotrc/docs/incidents/scripted-delete-removed-neighbor.md
