# 由来の番号ポインタが一般化を省き、委譲先で番号の種類がずれた

## 経緯

rule の由来は `由来: dotrc#N` の 1 行ポインタで書き、指す先は規約を入れた PR とする運用だった
（PR 本文が経緯の保存先で、別の台帳を持たない前提）。

規約の追加を 2 本の委譲に分けたとき、委譲元が HOW に由来番号として起点の issue 番号を
指定した。rule が求めていたのは PR 番号なので、委譲先 2 本がそれぞれ食い違いに気づき、
別々に訂正した。委譲先の振り返りは「HOW では番号をプレースホルダにする」を提案した。

同じ頃、repo の作り直しを計画する中で、ユーザーから「PR 番号や Issue 番号は弱い。一般化して
説明するべきものを省いているにすぎない」と指摘された。

## 観測

コマンドの実測は無い。観測したのは次の 2 点で、いずれも会話上・委譲の経過上のもの。

- HOW に書いた issue 番号を、委譲先 2 本が rule の記述（PR を指す）と照合して別々に書き換えた
- 番号ポインタを置いた節の本文に、適用時の見分け方が書かれていない箇所があった
  （経緯が番号の先にしか無い）

repo 作り直しで PR が旧 repo に残る・issue の transfer で番号が変わる、という帰結は GitHub の
仕様からの推論で、この件では再現していない。

## 直し方

プレースホルダ化は番号の種類のずれだけを塞ぎ、番号の先へ一般化を追いやる形も、番号が repo に
従属する形も残る。そこで番号ポインタ自体をやめた。

- rule / skill / agent 定義には一般化した失敗の型だけを書き、見分け方として書けない記録は落とす
- 具体的な経緯は `docs/incidents/<slug>.md` に 1 件 1 ファイルで置き、節の末尾から
  `実例: dotrc/docs/incidents/<slug>.md` で参照する

既存の `由来: dotrc#N` 行は後続の作業で移し替えた（一般化して本文へ残すか、incident doc へ移すか、
記録として落とすかを箇所ごとに振り分けた）。

## 反映先

- `dot/claude/rules/rule-authoring.md`「由来は一般化して本文に書き、経緯は incident doc に置く」
- harness を足す経路の skill（`harness-from-feedback` / `harness-from-retrospective` /
  `delegate-to-worktree` / `implement-and-review`）から上の節への参照
- `.github/ISSUE_TEMPLATE/*.md` の `## 由来` 節のコメント
